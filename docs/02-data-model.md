# 02. Data model (Firestore + Storage)

## General conventions
- Collection names: plural, camelCase. Field names: camelCase.
- ALL enums: English, UPPER_SNAKE_CASE (e.g. `IN_PROGRESS`, `TECHNICIAN`, `BEFORE`).
- Time: Firestore `Timestamp` (UTC). Do not store date strings like "24/11/2026".
- Coordinates: object `{ lat: number, lng: number }` EVERYWHERE (Firestore and API). Do not use `GeoPoint`.
- Distance: meters. Compass bearing (`heading`): degrees 0-360, 0 is North. `accuracy`: meters.
- Every document has `schemaVersion: 1`.
- "Server-only" = only the server (firebase-admin) may write; clients are blocked by Security Rules.

**Photo**
| Field | Type | Meaning |
|---|---|---|
| `photoId` | string (UUID) | Generated by mobile |
| `phase` | `BEFORE \| AFTER` | |
| `storagePath` | string | See the Storage section |
| `sha256` | string | Hash of the final image file (after watermarking), computed on the device |
| `capturedAt` | Timestamp | Phone time when the photo was taken |
| `location` | `{lat, lng}` | Coordinates when the photo was taken |
| `accuracy` | number | m |
| `heading` | number \| null | degrees; null if the device has no sensor |
| `mockLocationDetected` | boolean | Android reported a mock location |
| `deviceId` | string | App-install UUID stored locally |
| `source` | `"IN_APP_CAMERA"` | Always this value; reject anything else |
| `sizeBytes` | number | |

**Signature**: `{ storagePath, sha256, signedAt: Timestamp }`

**Flag**: `{ code, severity: "INFO" | "WARNING" | "CRITICAL", detail: string | null }`. Valid `code` values:
- `MOCK_LOCATION`: a photo or check-in has `mockLocationDetected = true`
- `PHOTO_FAR_FROM_TICKET`: photo coordinates are more than `GEOFENCE_RADIUS_M` from `ticket.location`
- `PHOTO_TIME_OUTSIDE_WINDOW`: `capturedAt` is outside the valid window (docs/06)
- `CLOCK_SKEW`: device clock deviates abnormally from server time (docs/06)
- `DUPLICATE_HASH`: `sha256` matches a photo in another report
- `LOW_GPS_ACCURACY`: `accuracy` > `GPS_MAX_ACCURACY_M`

Missing files and hash mismatches return API errors before a report is created (docs/04).

## Collection `technicianLocations`  (id = technician uid)
Holds on-duty status + the LATEST location (overwritten), with no history. The technician's own client may write.
| Field | Type | Meaning |
|---|---|---|
| `isOnDuty` | boolean | Technician toggles "Start shift" in the app |
| `location` | `{lat, lng}` \| null | null if not yet available |
| `accuracy` | number \| null | m |
| `heading` | number \| null | degrees |
| `updatedAt` | Timestamp | Use `serverTimestamp()` |
| `schemaVersion` | number | |

Dispatchers treat a technician as "on duty" when `isOnDuty = true`. If `now − updatedAt > LOCATION_STALE_AFTER_S`, additionally show "signal lost".
When assigning a job, the server checks that `isOnDuty = true` (docs/04).

## Firebase Storage: paths
```
reports/{ticketId}/{clientReportId}/{phase}_{photoId}.jpg      (phase: before | after, lowercase in the file name)
reports/{ticketId}/{clientReportId}/signature.png
```
- Photo filenames use the `before_` or `after_` prefix, the photo's UUID, and the `.jpg` extension. Their content type is `image/jpeg`.
- The optional signature uses the exact filename `signature.png` and content type `image/png`.
- Each file is limited to `PHOTO_MAX_BYTES`.
- Clients may only create new files; they may NOT overwrite or delete.
